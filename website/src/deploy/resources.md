# 磁盘、资源与并发

## 磁盘占用

除实际文件外，还需预留下载暂存、待上传文件、分片合并、预览/转码、BT 副本、数据库、镜像和备份空间。远端存储不代表服务器无需磁盘。

```bash
df -h
df -i
docker system df
```

同时检查容量和 inode，不直接删任务目录或用 `prune --volumes` 腾空间。

## 默认保护值

| 配置 | 默认 | 说明 |
| --- | --- | --- |
| `TG_MIN_FREE_DISK_GB` | 8 GiB | Telegram 下载保留空间 |
| `TG_DISK_WATERMARK_RECHECK_MS` | 30 秒 | 空间不足后的复查间隔 |
| `TG_DISK_WATERMARK_MAX_WAIT_MS` | 0 | 默认无空间等待总超时 |
| `MAX_UPLOAD_CHUNK_MB` | 32 MiB | 单分片上限 |
| `MAX_CHUNK_UPLOAD_GB` | 20 GiB | 单分片会话总量上限 |
| `CHUNK_GLOBAL_BUDGET_GB` | 40 GiB | 全局分片预算，不小于单会话上限 |
| `CHUNK_DISK_RESERVE_GB` | 8 GiB | 分片保留空间 |
| `CHUNK_SESSION_TTL_MS` | 24 小时 | 分片会话有效期 |

已有部署可能覆盖默认值。浏览器以服务端实时能力为准；反代请求体限制和应用上传预算是两层设置。

## 下载并发

入口：**设置 → 维护 → 高级任务设置**。

| 设置 | 默认与范围 | Bot 命令 |
| --- | --- | --- |
| 单文件分片并发 | 默认 4；4/6/8/10/12，10/12 需确认 | `/download_workers` |
| 同时下载文件数 | 默认 2；1–10，实际上限 `min(10, max(2, 启用账号数 × 2))` | `/file_concurrency` |

提高并发会增加内存和在途数据，实际速度仍受网络和存储影响。

下载槽与上传阶段分开；等待上传不占下载槽，但仍占暂存空间。默认值下先观察磁盘、内存、网络和目标速度，一次只改一项。

FloodWait 按 Telegram 要求等待，“继续”不能解除冷却。

## 备份空间

协调备份预检需要目标至少能容纳 **未压缩 `/data` + 数据库大小 + 512 MiB**。建议备份到另一块盘并加密异地保存。远端对象、下载器配置和外部 BT 目录另行备份。
