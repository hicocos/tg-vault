# OpenList 原生接入

通过原生 API 连接已运行并挂载好存储的 OpenList。TG Vault 不安装 OpenList，也不配置其背后的云盘驱动。

## 1. 在 OpenList 准备目标

1. 完成云盘挂载，确认目标目录可写。
2. 创建专用 OpenList 用户，限制到目标目录，授予上传、读取及所需删除权限。
3. 确认该用户可上传文件，且文件最终出现在背后云盘。

## 2. 在 TG Vault 添加

打开 **设置 → 存储 → 添加存储 → OpenList**：

| 字段 | 内容 |
| --- | --- |
| 存储名称 | 显示备注 |
| 服务地址 | 站点根地址，如 `https://openlist.example.com`；反代在子路径时包含实际前缀 |
| 根目录 | OpenList 虚拟路径，如 `/OneDrive/Archive`，默认 `/` |
| 用户名 / 密码 | 专用 OpenList 用户凭据，不是背后云盘账号密码 |

服务地址不带 `/dav`、`/api/fs` 或分享路径。根目录填写 OpenList 虚拟目录，不是服务器路径或分享链接。

点击 **验证并添加**，系统会实际检查写入，不接受只读目录。添加后不会自动切换默认，按需设置。

## 与 WebDAV 的区别

- 原生 API 使用站点地址、虚拟目录和用户密码，TG Vault 自动登录获取 Token。
- WebDAV 类型填写 DAV URL，使用独立的认证与安全设置。
- 原生接入要求公网 HTTPS，WebDAV 的内网开关不对此生效。
- 不支持游客、手填 Token、交互式二次验证或元信息密码，需使用适配的专用用户和目录。

## 验证和长期维护

首次转存后核对 TG Vault 文件记录、OpenList 目录和背后云盘。网关接收成功不代表云盘已完成保存。

避免多个系统同时写入同一受管理目录，以免重名冲突。

移除 TG Vault 账户不删除远端文件。远端文件、OpenList 数据与网关凭据需另行备份。
