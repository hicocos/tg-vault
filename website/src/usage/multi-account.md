# 多账号调度

TG Vault 可同时管理多个 Telegram 个人账号，为频道下载和订阅按来源权限、冷却与占用选择账号。调度以文件为单位，不是把一个文件拆给多个账号，也不保证增加账号就提速。

## 添加与启用

1. 在 **设置 → Telegram → Telegram Bot 连接** 配置 API ID/Hash 等凭据，详见[连接与授权](/deploy/telegram)。
2. 找到 **Telegram 用户账号 → 添加账号**，选择二维码或手机号登录。扫码入口是 Telegram **设置 → 设备 → 连接桌面设备**；手机号须含国家或地区区号，再输入验证码，必要时输入两步验证密码。
3. 新绑定账号自动启用。依次添加其他账号，核对账号名与状态；已停用的账号点击 **重新启用**，就绪后才参与调度。
4. 用实际账号确认能读取目标原帖和历史，再提交小范围[频道下载或订阅](/usage/subscriptions)。Bot 认证不能代替来源权限；私有来源通常须自行加入。

停用保留登录凭证；删除账号会删除 TG Vault 保存的凭证，不删除已下载文件。Session 按密码保护，泄露后应在 Telegram 撤销活动会话。

## 账号怎样分配

系统排除停用、离线、登录失效、冷却中或无来源权限的账号，优先选择已确认可读、当前负载较低的账号。同等条件下轮换分配；账号忙碌或冷却时等待，没有可用账号则提示错误。

账号卡片可查看调度权重，目前不提供修改入口。权重不代表带宽配额或固定分配比例。

## 文件、扫描与并发

一个文件的分片使用同一账号。短暂网络中断可续传；需要换账号重试时，可能重新读取文件。FloodWait 按 Telegram 要求等待。

扫描与文件下载分别调度，可能使用不同账号，但共享账号冷却。

**设置 → 维护 → 高级任务设置** 中，“同时下载文件数”默认 `2`，可设 `1–10`，实际可选上限随已启用账号数变化。添加账号只提高可设置上限，不自动提高当前并发，也不增加服务器带宽或存储上传额度；单文件分片并发是另一项设置。

## 查看状态与恢复

账号卡片显示状态、**下载中**数量、**调度权重**和**所属 DC**。下载中不包含扫描；DC 是登录会话的主数据中心，不是用户位置或文件所在 DC。“可用”也不代表已验证所有来源。

FloodWait 按 Telegram 要求等待，卡片会在适用时显示预计恢复时间。不要反复启停或增加并发规避等待。

系统自动恢复可恢复的连接；Bot 与个人账号独立连接。登录个人账号不会让它读取 Bot 私聊。

## 常见问题

| 现象 | 处理 |
| --- | --- |
| 登录已失效 | 点击 **重新登录**，使用原 Telegram 账号；完成后核对实际连接状态 |
| 可用但读不到来源 | 用该账号打开原帖与历史，核对私有来源成员身份、内容限制和消息是否存在 |
| 新请求等待或暂时受限 | 查看占用和恢复时间；冷却结束前等待，不靠“继续”解除 |
| 持续异常、无法恢复 | 查看卡片错误及后端日志，排查网络与资源；避免重启后端中断其他下载 |
