# 任务、进度与重试

Web **任务**显示上传、Bot 文件、频道下载和订阅任务；启用 qBittorrent 后还会显示 BT。Bot `/tasks` 显示当前用户或聊天可管理的任务。

## 状态不是只有成功或失败

| 状态/阶段 | 含义与操作 |
| --- | --- |
| 等待、排队 | 尚未传输，检查排队原因、磁盘与依赖 |
| 扫描 | 正在发现消息或文件，总量可能未知 |
| 下载 | 正在读取来源，不代表已写入目标存储 |
| 上传/处理 | 存储写入、入库或媒体处理尚未结束 |
| 暂停中/已暂停 | 停止后续读取，在途请求或存储写入仍可能完成 |
| 等待冷却 | 按 Telegram 或提供方要求等待，“继续”不能解除 |
| 失败/中断/需重试 | 查看第一处错误，可能已有部分结果 |
| 完成 | 处理结束，仍需查看成功、失败和跳过数量 |
| 已取消/已关闭 | 不再继续，已保存文件不会自动撤回 |

BT 的元数据、文件选择和清理阶段见 [qBittorrent](/usage/qbittorrent)。订阅是持续扫描计划，不是一次性文件任务。

## 百分比与速度的边界

- 批量 100% 表示已发现条目处理完，不等于全部成功。
- 扫描总量未知时不显示百分比。
- 下载速度与存储上传速度分别计算；下载完成后仍可能等待写入和入库。
- 网关返回成功不代表背后云盘最终可用。
- BT 下载与转存进度独立，存储确认并入库后转存才到 100%。

## 暂停、继续与取消

可用操作随任务来源和状态变化。Bot 提供 `/task_pause`、`/task_resume`、`/task_cancel` 和 `/stop_tasks`。

暂停不会立即中断所有在途操作，取消也不会回滚已保存文件。**BT 取消会删除下载器任务及源文件，即使已选择保留做种；已转存文件不受影响。** 执行前核对确认页。

## 失败后的安全处理顺序

1. 查看来源、任务 ID、失败阶段、目标和第一处错误。
2. 检查来源权限、冷却时间、磁盘空间与存储状态。
3. 修复后先恢复一个任务，核对结果再批量重试。

Web 上传恢复会返回上传队列，可能需重新选择本地文件。普通 Telegram 保存任务在重启后若无法确认远端写入结果，会报错要求核对，不会仅凭同名对象认领或删除文件。

## 清理历史不是清理文件

清理已结束任务记录不会删除文件、取消订阅或停止做种。移除存储账户的影响与限制见[账户维护与移除](/storage/#账户维护与移除)。
