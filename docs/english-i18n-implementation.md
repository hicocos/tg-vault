# TG Vault 全面支持英语实施文档

## 1. 目标

在保持现有中文体验和业务行为不变的前提下，使 TG Vault 的 Web 端与 Telegram Bot 全面支持英语，并建立可继续扩展日语、西班牙语等其他语言的国际化基础。

本阶段支持：

- 简体中文：`zh-CN`
- 英语：`en`

语言策略：

- **默认语言：简体中文**
- **缺少翻译时的回退语言：简体中文**
- 无法识别用户语言时使用简体中文
- 现有用户升级后继续使用简体中文，不自动切换成英语

## 2. 实施原则

1. 中文保持默认，英语作为用户主动选择或自动识别后的可选语言。
2. 所有用户可见文案进入统一翻译目录，业务代码不直接依赖中文或英文展示文本。
3. 命令名、回调数据、状态值和数据库枚举保持稳定，只翻译展示内容。
4. Web 与 Telegram Bot 分别保存语言偏好，暂不自动互相同步。
5. 日期、时间、数字、文件大小和复数根据当前语言格式化。
6. 国际化只改变展示层，不改变认证、下载、订阅、存储和任务调度行为。
7. 新增语言时主要增加语言配置与翻译目录，不重复改造业务流程。

## 3. 语言选择与回退规则

### 3.1 Web 端

语言优先级：

1. 用户在 Web 端明确选择的语言
2. 浏览器语言
3. 简体中文

用户选择结果保存在浏览器本地。浏览器语言不受支持、翻译键缺失或语言文件加载失败时，统一回退到简体中文。

### 3.2 Telegram Bot

语言优先级：

1. 用户在 Bot 中明确选择并持久化的语言
2. Telegram 用户的 `language_code`
3. 简体中文

Bot 语言偏好按 Telegram `user_id` 保存。同一用户在不同聊天中默认使用同一种界面语言；聊天保存路径、存储目标和通知投递设置仍保持现有作用域，不与语言偏好混合。

## 4. Web 端实施范围

### 4.1 语言入口

- 保留首次设置页和登录页顶部的语言切换。
- 已登录页面提供始终可达的语言入口，避免侧栏折叠后无法切换。
- 将当前中英文双按钮改为配置驱动的语言选择器，为后续增加更多语言预留空间。

### 4.2 文案覆盖

全面迁移 Web 用户可见文案，包括：

- 登录、首次初始化和双重验证
- 文件浏览、上传、搜索、移动、重命名、删除和分享
- 上传中心、任务中心和进度状态
- 设置、存储账户和 Telegram 配置
- Telegram 用户账号管理
- 频道订阅、广告过滤和人工纠正
- 确认框、通知、空状态、错误提示和无障碍标签

### 4.3 格式化与错误处理

- 统一日期、时间、数量、时长和文件大小格式化。
- 后端业务错误逐步改为稳定的错误码和参数，由 Web 根据当前语言展示。
- 第三方服务的原始错误保留用于诊断，但不作为主要用户文案。

## 5. Telegram Bot 实施范围

### 5.1 `/start` 与语言设置

- 首次使用或尚未明确选择语言时，`/start` 显示双语语言选择：`简体中文`、`English`。
- 选择语言后，在同一交互中继续现有欢迎页或 PIN 认证流程。
- 已保存语言偏好的用户执行 `/start` 时，直接使用其语言，同时保留语言设置入口。
- 新增 `/language` 命令，并可提供 `/lang` 别名，允许用户随时修改语言。

### 5.2 Bot 文案覆盖

全面翻译 Bot 用户可见内容，包括：

- 欢迎、认证、PIN、2FA、退出和帮助
- 命令说明和功能主页
- Inline Keyboard 按钮
- Callback 提示、警告和确认信息
- 文件、上传、存储和任务面板
- 频道下载、订阅管理和失败重试
- 通知设置、任务通知、安全告警和通知摘要
- 日期、数量、文件大小和进度信息

### 5.3 Telegram 原生命令菜单

- 注册默认菜单，使用简体中文。
- 注册中文菜单和英文菜单。
- 各语言的命令名称与顺序保持一致，仅翻译命令描述。
- 菜单同步失败沿用现有隔离策略，不应影响 Bot 主功能就绪状态。

### 5.4 安全边界

语言选择和国际化流程只能读取或保存语言偏好、重新渲染消息，不得：

- 连接、恢复或启用个人 Telegram 账号
- 修改个人账号 Session
- 启动订阅扫描或任务恢复 Worker
- 修改 Telegram 用户允许列表或直接完成认证
- 重启、重新绑定或重新配置 Bot

现有“个人账号仅允许通过登录完成或明确启用而连接”的安全规则必须继续通过回归测试。

## 6. 国际化结构

Web 与 Bot 分别维护翻译目录，但采用一致的语言代码和命名原则：

```text
locales/
├── zh-CN/
│   ├── common
│   ├── auth
│   ├── files
│   ├── tasks
│   ├── settings
│   └── telegram
└── en/
    ├── common
    ├── auth
    ├── files
    ├── tasks
    ├── settings
    └── telegram
```

翻译键使用稳定的语义名称，不使用整句中文作为键。语言注册表统一维护：

- 语言代码
- 原生语言名称
- 浏览器与 Telegram 语言别名
- 文本方向
- 日期与数字格式区域
- 翻译资源加载方式

## 7. 实施阶段

### 第一阶段：国际化基础

- 统一语言代码、默认语言和回退规则。
- 建立语言注册表、翻译目录和统一格式化工具。
- 建立 Bot 用户语言偏好存储。
- 为现有 Bot 用户保留简体中文偏好。

### 第二阶段：Web 全面英语化

- 改造语言选择器和全局入口。
- 清理所有 Web 用户可见的中文硬编码。
- 补齐英语翻译、动态格式化和错误码映射。

### 第三阶段：Telegram Bot 全面英语化

- 实现 `/start` 语言选择和 `/language` 命令。
- 国际化命令菜单、消息、按钮、面板和通知。
- 确保后台主动通知使用接收用户的语言。

### 第四阶段：测试与发布

- 增加翻译目录完整性、插值变量和硬编码扫描测试。
- 对中文、英文分别执行 Web 和 Bot 核心用户流程测试。
- 执行 Telegram 账号连接安全回归测试。
- 完成构建、容器部署和生产环境验证后再发布。

## 8. 验收标准

满足以下条件后，可对外声明“全面支持英语”：

- Web 端切换英语后，所有主要页面和操作流程无中文残留。
- 首次设置、登录、错误提示和安全确认完整支持英语。
- Bot 的命令、消息、按钮、回调提示和主动通知完整支持英语。
- 中文仍是默认语言和缺失翻译时的回退语言。
- 现有用户升级后保持中文，不发生意外语言切换。
- 刷新页面、Bot 重启和服务重启后，明确选择的语言仍然有效。
- 不支持的语言和缺失翻译能够安全回退到简体中文。
- 各语言下的关键操作、权限校验和安全提示语义一致。
- 国际化改动不会触发或扩大个人 Telegram 账号连接范围。
- 新增第三种语言时，无需重写现有业务流程。
